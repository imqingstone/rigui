## 1. 一句話

每天一題的排行程小遊戲。今天有一位旅人來到驛站，請你替他把一天的事排進十二個時辰。排得順應時辰，值班的大臣就會亮起來。

- 站名：日晷。副標：替旅人排一天。
- 類型：單人、每日一題、解謎小品。手機直向為主，一局三到五分鐘。
- 純靜態網頁：無後端、無登入、無建置步驟、無外部套件。進度只存在自己的瀏覽器。
- 青石驛的一員，放在青石驛的「驛站後院」，與靈蘭並列。

### 1.1 為什麼這樣設計

靈蘭的驚喜在結局揭曉，破關後就少了回去玩的理由。日晷一開始就把「讓人想每天回來」放進設計：

- 每天一題，所有人同一題，玩完就等明天（類似 Wordle）。
- 題目跟著真實的節氣走，每兩週左右換一次感覺。
- 可以收集節氣與旅人，連續天數會讓驛站庭院慢慢長出東西。
- 結果可以複製成一段文字分享到社群。

## 2. 主題與內容來源

### 2.1 十二時辰與值班的官

傳統上把一天分成十二個時辰，每個時辰有一條經絡「當值」，後世稱為「子午流注」。遊戲裡用《素問・靈蘭秘典論》的「十二官」稱呼它們，與靈蘭同一個世界觀。

| 時辰 | 時間 | 值班 | 官名（靈蘭秘典論） | 原文 |
|---|---|---|---|---|
| 子 | 23–1 | 膽 | 中正之官 | 膽者，中正之官，決斷出焉 |
| 丑 | 1–3 | 肝 | 將軍之官 | 肝者，將軍之官，謀慮出焉 |
| 寅 | 3–5 | 肺 | 相傅之官 | 肺者，相傅之官，治節出焉 |
| 卯 | 5–7 | 大腸 | 傳道之官 | 大腸者，傳道之官，變化出焉 |
| 辰 | 7–9 | 胃 | 倉廩之官（與脾同） | 脾胃者，倉廩之官，五味出焉 |
| 巳 | 9–11 | 脾 | 倉廩之官 | 同上 |
| 午 | 11–13 | 心 | 君主之官 | 心者，君主之官也，神明出焉 |
| 未 | 13–15 | 小腸 | 受盛之官 | 小腸者，受盛之官，化物出焉 |
| 申 | 15–17 | 膀胱 | 州都之官 | 膀胱者，州都之官，津液藏焉，氣化則能出矣 |
| 酉 | 17–19 | 腎 | 作強之官 | 腎者，作強之官，伎巧出焉 |
| 戌 | 19–21 | 心包（膻中） | 臣使之官 | 膻中者，臣使之官，喜樂出焉 |
| 亥 | 21–23 | 三焦 | 決瀆之官 | 三焦者，決瀆之官，水道出焉 |

- 時辰與經絡的對應是後世依《內經》發展出來的說法（金代何若愚《子午流注針經》等），遊戲中要這樣標明，不能說成《內經》原文。
- 遊戲裡引用的原文，實作時請逐字核對維基文庫的《黃帝內經》，並在說明頁附上出處連結。

### 2.2 一天與四季

可以引用的《內經》原文（實作時一樣要核對）：

- 《靈樞・順氣一日分為四時》：「以一日分為四時，朝則為春，日中為夏，日入為秋，夜半為冬。」
- 《素問・生氣通天論》：「故陽氣者，一日而主外，平旦人氣生，日中而陽氣隆，日西而陽氣已虛，氣門乃閉。」
- 《素問・四氣調神大論》的四季作息（靈蘭也用過）：春夏「夜臥早起」、秋「早臥早起」、冬「早臥晚起，必待日光」。

### 2.3 內容原則（很重要）

- 這是古代經典的文化介紹，**不寫任何療效、保健或醫療建議**。頁尾寫明「本遊戲是古代經典的文化介紹，不構成任何醫療或健康建議」。
- 說法一律寫成「古人認為」「傳統的說法是」，不寫「這樣做對身體好」。
- 食物只用素食，不出現任何葷食，也不出現五辛（蔥、蒜、韭、薤、興渠）。
- 用台灣繁體中文慣用語與全形標點，避開中國大陸用語。
- 避開這些詞：不必、未必、值得、真正、扛、溫柔、看見、落地、節奏、穩穩、允許自己、你不需要。也少用「不是……而是……」的句型。測試要自動檢查。

## 3. 核心玩法

### 3.1 畫面

- 中央是一個**日晷圓盤**，分成十二格，每格是一個時辰，標著時辰名、時間與值班的官。
- 下方是今天要排的**行程卡片**。
- 上方是今天的旅人、節氣與日期。

### 3.2 操作

- **點選放置**，不用拖曳：先點一張行程卡，再點圓盤上的一格，就放進去。點已放好的卡片可以拿回來。
- 每格最多一張卡。沒放卡片的時辰，視為「休息」。
- 全部排好後，按「定案」看結果。定案前可以隨意調整。

### 3.3 行程卡

每張卡有：名稱、一句描述、適合的時辰、不適合的時辰。資料放在 `data.js`。

| 起身散步 | 卯 | 子、丑 | 「平旦人氣生」 |
| 早膳（粥、饅頭、豆漿） | 辰 | 子、丑、亥 | 辰時胃當值 |
| 讀書 | 巳、申 | 子、丑 | |
| 勞動・幹活 | 巳、未、申 | 子、丑、亥 | |

| 小憩 | 午 | 子以外的夜裡 | 日中陽氣隆，古人有午休的習慣 |

| 晚膳 | 酉 | 子、丑 | |

### 3.4 計分

- 每格 0 到 3 分，十二格滿分 36。
  - 放在「適合」的時辰：3 分，值班的官亮起來。
  - 放在中性的時辰：1 分。
  - 放在「不適合」的時辰：0 分，值班的官暗下來。
  - 空格（休息）：依時辰給分。子、丑休息是 3 分；白天大部分時辰休息是 1 分。
- 旅人的特殊需求（3.5）沒達成，扣分或不能拿最高評等。
- 評等（暫定）：32 以上「日正當中」、26 以上「晴」、18 以上「多雲」、以下「陰」。數值以模擬調整。
- 結果畫面逐格說明：為什麼亮、為什麼暗，附上傳統說法與原文。

### 3.5 旅人

每天一位，各有特殊需求，讓同一個時辰在不同天要排不同的事：

- **書生**：要讀書至少兩個時辰。
- **商人**：要「趕路」連續兩個時辰。
- **農夫**：卯或辰要「下田」。
- **畫師**：要一個安靜的時辰作畫（巳或申）。
- **老者**：要早睡，亥時就要就寢。
- **旅人本人（青石旅人）**：沒有特殊需求，純粹順時。

旅人的對白與描述要有個性，但不要太長。

### 3.6 節氣的影響

- 依台灣日期判斷當天的節氣。節氣時刻可以直接複製 `imqingstone/sishi` 專案的 `docs/terms.js`（1900–2101 年，已依天文計算並驗證過）。
- 四季作息會改變部分時辰的分數，依《四氣調神大論》：
  - 春、夏「夜臥早起」：亥時還沒睡不扣分，卯時起身加分。
  - 秋「早臥早起」：亥時要就寢。
  - 冬「早臥晚起，必待日光」：卯時繼續睡不扣分，甚至加分。
- 圓盤上依季節顯示白天與夜晚的範圍（可以用台北的日出、日落時間，四時專案有均時差的算法可以參考）。

## 4. 每日題目

- 每天的題目由**台灣日期**產生固定的亂數種子，所有人同一天拿到同一題。
- 每題包含：旅人一位、行程卡六到八張、當天節氣。
- 要保證每一題都有能拿到最高評等的排法。用程式驗證，並在測試裡對未來一年的每一天都檢查。
- 一天只算一次成績（第一次按「定案」的結果）。之後可以重排看看，但不影響紀錄。
- 另有「練習」模式，隨機出題，不計入紀錄。

## 5. 收集與回訪

- **節氣圖鑑**：在某個節氣期間玩過一次，就收錄那一頁。每頁有節氣名稱、日期範圍、三候（物候）、一句介紹，以及一張插畫或小圖示。一年二十四頁。
- **旅人圖鑑**：遇過的旅人，收錄他的介紹。
- **驛站庭院**：連續天數增加時，庭院慢慢多一棵樹、一盞燈、一張石凳。中斷了不清空，只是停止成長。
- **分享**：結果畫面有「複製結果」按鈕，產生一段文字，例如：

  ```
  日晷・11/23 小雪
  ☀☀🌤☀☀☁
  ☀🌤☀☀☀☀
  32/36 日正當中
  imqingstone.github.io/rigui/
  ```

  每個符號代表一個時辰的分數。不透露排法，方便在社群分享又不爆雷。

## 6. 技術與檔案

比照靈蘭的結構：

- `docs/`：網站本體（GitHub Pages：main 分支的 /docs）。
  - `engine.js`：規則，只寫純函式。計分、出題、驗證都在這裡，可以在 Node 中執行。
  - `data.js`：所有數值與文字（行程、旅人、節氣說明、原文）。
  - `terms.js`：節氣時刻（從四時複製）。
  - `app.js`、`index.html`、`style.css`：畫面。
- `tests/verify.js`：測試，執行 `node tests/verify.js`。至少檢查：
  - 未來一年每天的題目都有解，而且能拿到最高評等。
  - 計分規則與節氣影響。
  - 文字避開 2.3 的詞，且不出現葷食與五辛。
- 進度存在 `localStorage`（例如 `rigui.save`），讀寫都要包 try/catch。提供「匯出進度」「匯入進度」。

### 6.1 與青石驛一致的細節

- `<head>` 加上 `<meta name="format-detection" content="telephone=no">`。
- 頁尾放「回到青石驛」按鈕，附青石圖示（`qingstone.png`，可從 `imqingstone/yuebei` 專案的 `docs/` 複製），連到 `https://imqingstone.github.io/`。按鈕樣式比照月杯。
- 頁尾版權：「© 2026 日晷・古文屬公有領域，其餘內容為原創，未經同意請勿轉載」，在「公有領域，」後換行，不要拆開「未經同意」。
- 使用次數用 GoatCounter（code `imqingstone`）：
  - 頁面載入用標準的 count.js。
  - 每次「定案」送一個事件，path 為 `rigui-play`。
  - 頁尾讀取公開計數 `https://imqingstone.goatcounter.com/counter/rigui-play.json`，顯示「已有 N 位旅人排過一天」，沒有數字時隱藏。
- 手機寬度 320 到 430 都不能有橫向捲動；文字在 iPhone 上要清楚，插畫上的字要有淡底。
- 動畫要尊重「減少動態效果」的系統設定。

## 7. 插畫

請 Selene 用 GPT 畫，風格與青石驛一致：淡雅水墨、米白宣紙、低彩度，**圖裡不要有文字**。

- **主畫面圖示**：正方形 1:1。一座日晷，晷針的影子落在某個刻度上，背景淡淡的日與月。
- **首頁主視覺**：直式 9:16 與橫式 16:9 各一張，驛站庭院裡的日晷，一側留白放標題。
- **庭院成長圖層**（選用）：樹、燈、石凳，各自一張透明背景小圖，或改用 SVG 繪製。

## 8. 里程碑

每做完一個里程碑，**停下來給 Selene 預覽連結試玩**，等她確認再做下一個。

1. **核心玩法**：固定一題（書生、立冬），圓盤、點選放置、計分、結果畫面與逐格說明。附測試。
2. **每日題目**：日期種子、旅人輪替、節氣規則、保證有解的驗證、分享文字、練習模式。
3. **收集與回訪**：節氣圖鑑、旅人圖鑑、連續天數與庭院、進度匯出匯入。
